# Performance–Efficiency–Robustness Trade-offs Among Classical Machine Learning Models for Electrical Grid Stability Classification

Reproducibility repository for the study by **Naser Khatti Dizabadi**, Department of Electrical and Computer Engineering, The University of Tulsa.

## Overview

This repository reproduces the main computational workflow used to compare four classical machine-learning classifiers for electrical grid stability classification:

- Logistic Regression (LR)
- K-Nearest Neighbors (KNN)
- RBF Support Vector Machine (RBF-SVM)
- Random Forest (RF)

The study jointly evaluates clean-data predictive performance, computational efficiency, and robustness to Gaussian measurement noise and missing measurements.

## Dataset

The study uses the **Electrical Grid Stability Simulated Data** dataset from the UCI Machine Learning Repository.

UCI DOI: **10.24432/C5PG66**

The raw UCI dataset is not redistributed in this repository. Download `Data_for_UCI_named.csv` from UCI and supply its path to the scripts.

The reproducibility audit confirms:

- 10,000 observations and 14 original columns
- no missing values in the original dataset
- no exact duplicate rows
- `stab` deterministically reproduces `stabf` and is excluded to prevent target leakage
- `p1 = -(p2 + p3 + p4)` to floating-point precision and is excluded as redundant
- 11 final predictors: `tau1`–`tau4`, `p2`–`p4`, and `g1`–`g4`
- binary target: unstable = 1, stable = 0

## Experimental protocol

A stratified 80/20 train/test split with `random_state=42` is used. Preprocessing is fitted on training data only. Logistic Regression, KNN, and RBF-SVM use median imputation followed by standardization. Random Forest uses median imputation without scaling.

Final selected configurations:

| Model | Selected configuration |
|---|---|
| LR | `C=0.1` |
| KNN | `n_neighbors=15`, `weights="distance"` |
| RBF-SVM | `C=10`, `gamma=0.05` |
| RF | `n_estimators=200`, `max_depth=None`, `min_samples_leaf=1` |

The original candidate hyperparameter grid was not retained. This repository therefore does **not** attempt to reconstruct or invent that grid. It reproduces the selected configurations and the stored cross-validation results.

## Robustness protocol

### Gaussian noise

Models are trained on clean data and evaluated on perturbed held-out test data. Gaussian noise is scaled by each feature's training-set standard deviation at levels:

`0.05σ, 0.10σ, 0.20σ, 0.30σ`

Each nonzero level is evaluated across 30 repetitions. For repetition `r`, the random seed is `1000 + r`. One random-number generator is created per repetition and consumed sequentially across the four noise levels. Within each repetition and level, all models receive the same perturbed test set.

### Missing measurements

Cell-level feature values are removed under a missing-completely-at-random (MCAR) mechanism at rates:

`5%, 10%, 20%, 30%`

Each level is evaluated across 30 repetitions. For repetition `r`, the random seed is `2000 + r`. One random-number generator is created per repetition and consumed sequentially across levels. All models receive the same missingness mask within each repetition and level. Missing values are replaced using medians learned from the clean training set.

## Statistical analysis

Robustness is summarized using mean F1-score and variation across 30 perturbation repetitions.

The reported 95% intervals are calculated as:

`mean ± 1.96 × standard error`

These intervals characterize variation across simulated degradations on the fixed held-out test set and are not population-level generalization confidence intervals.

Pairwise model comparisons use two-sided paired Wilcoxon signed-rank tests on matched repetitions. Holm correction controls the family-wise error rate across the six pairwise model comparisons separately within each condition and degradation level.

## Efficiency benchmark

Efficiency is measured on the full 2,000-sample test batch using:

- one untimed warm-up prediction
- 20 timed repetitions
- median batch latency
- interquartile range (IQR)
- one-thread numerical execution during timing
- `n_jobs=1` for KNN and Random Forest
- serialized size of the complete fitted pipeline

Exact latency and serialized size can depend on hardware, operating system, library versions, numerical runtimes, and serialization behavior. Therefore, rerunning the benchmark is intended to reproduce the **methodology and qualitative trade-offs**, not guarantee identical timing values on different environments.


## Archived reference results

The `results/archived/` directory contains the retained original result tables used as manuscript reference outputs. Independently rerun outputs are stored separately in `results/` with names such as `*_reproduced.csv`.

This separation is intentional: it preserves the exact study record while allowing readers to rerun the workflow and inspect any small environment-dependent differences.

## Reproducibility status

The repository scripts reproduce:

- the frozen train/test split
- selected-model five-fold cross-validation F1 scores
- clean held-out test metrics
- Gaussian-noise robustness protocol and results to manuscript precision, with very small environment-dependent differences in a few values
- missing-measurement robustness results to manuscript precision
- 95% interval construction
- paired Wilcoxon/Holm statistical protocol
- the efficiency-benchmark methodology

Small environment-dependent differences can occur in Random Forest predictions under Gaussian perturbation and consequently in RF-dependent Gaussian statistical comparisons. The archived manuscript results remain the reference values used in the paper; reproduced outputs are retained separately rather than silently replacing them.
